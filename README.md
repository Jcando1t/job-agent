# 求职 Agent

一个逐步构建的个人求职工作台。当前以简历工作台为入口，支持上传/粘贴已有文本简历、整理个人资料，并基于原稿和资料编辑升级版本；数据保存在本地 SQLite 数据库。

目标运行环境为 Python 3.11。运行前可以用 `python --version` 检查；若本机没有 Python 3.12，请使用 Python 3.11 创建虚拟环境。

## 本地运行

在 PyCharm 的项目终端中运行：

```powershell
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

然后在浏览器打开 <http://127.0.0.1:8000>。按 `Ctrl+C` 停止服务。

首次配置时可以复制 `.env.example` 为 `.env`。需要使用 AI 改进时填写 `DEEPSEEK_API_KEY`；也兼容系统环境变量名 `DEEP_SEEK_API_KEY`。密钥只放在本地 `.env` 或系统环境变量中，不能提交到 Git。

## 数据库迁移

业务读写使用 SQLAlchemy 2，应用启动时由 Alembic 执行 `upgrade head`。旧版数据库已在本地备份并登记到当前迁移基线；启动时会把旧数据库中的简历图片和已解析文本复制到本地文件目录，并保留原有数据库内容。

新建空数据库可运行：

```powershell
python -m alembic upgrade head
```

若要手动登记其他已有数据库，先停止应用并备份数据库。确认表结构与模型一致后，可运行 `python -m alembic stamp head` 登记基线；`stamp` 只记录版本，不会创建或删除业务表。不要对已存在但未登记的数据库直接运行初始 `upgrade`。

求职方向、岗位和个人资料写入项目的 `data/job_agent.db`，该目录已加入 `.gitignore`，不会提交到 Git。

## 当前功能

- 新增、查看、编辑、暂停、启用和删除多个求职方向
- 为每个方向填写岗位名称、搜索关键词和多个城市
- 北京、天津可直接选择，也可以填写其他城市
- 数据保存在本地，重新启动后仍然存在
- 手动新增岗位，也可把 BOSS 收藏岗位页面文字、链接和 JD 粘贴整理后导入；支持查看、编辑和删除
- 可启动专用 Chrome，用户登录 BOSS 后同步收藏列表或从收藏列表打开的岗位详情页；只预览读取到完整 JD 的岗位，再逐条确认导入，不保存 BOSS 密码
- 岗位记录可进入投递准备页，岗位卡片默认折叠；选择已审核简历后，可一键在专用 Chrome 打开对应沟通页并预填招呼语，消息和简历附件仍需用户分别确认后发送
- 岗位可填写公司、城市、来源、原始链接、岗位描述，并关联一个求职方向
- 岗位记录支持未处理、收藏、不合适、已投递、面试中和已结束状态，并记录备注与下一步行动；相同原始链接或相同岗位信息会被拒绝重复保存
- 手动记录个人信息、教育/工作经历、项目、技能和成果，并可编辑或删除
- 保存 `.txt` / `.md` 简历原文，支持刷新后重新载入
- 上传 `.txt` / `.md` / `.pdf` / `.docx` 简历并提取文字；原始文件保存在 `FILE_STORAGE_DIR` 指定的本地目录
- 本地保存 PNG/JPG 简历图片并预览；通过本地 OCR 自动识别文字，校对后关联到图片原稿
- 把个人资料作为后续简历升级的事实依据
- 在升级区并排查看原始简历和可编辑的升级草稿
- 生成和审核时按 A4 一页目标控制篇幅；草稿会显示估算行数，预计超页时禁止保存，避免导出后才发现超出一页
- 刷新后恢复最近待审核草稿；模型调用失败会保留任务状态和错误原因，并在改进页面提示
- 对工作经历和项目经历中的条目运行本地 STAR 提示及修改摘要；编辑草稿后重新检查
- 保存与原始简历关联的可编辑升级版本
- 审核保存后的版本可下载为 Word（DOCX）、一页 PDF 或 Markdown；可选个人照片会嵌入 Word/PDF 简历抬头，不会改写原稿和数据库中的版本正文
- 可选粘贴岗位 JD，生成岗位定制简历和打招呼语；审核时可以分别编辑，保存时与简历版本一起保留
- AI 改进区可以直接选择已保存岗位，自动带入岗位名称、公司和 JD；确认后的简历版本保留岗位记录 ID 与 JD 快照
- 根据岗位名称、JD 和改进重点在本地个人知识库中做关键词检索，最多选取 8 条相关经历交给模型
- 将 JD 本地整理为岗位职责、硬性要求、优先条件和关键词，并逐条列出命中的原始简历/个人资料或未找到依据的缺口；没有个人知识库也可以先用原始简历完成流程
- 简历改进使用 LangGraph 编排最小 Agent 图：分析 JD → 检索资料 → 生成草稿 → 质量检查 → 根据一页结果路由到“等待审核”或“需要修改”；具体分析器、检索器、模型客户端和检查器仍是可替换的独立服务

## 运行测试

```powershell
python -m unittest discover -s tests -v
```

图片 OCR 使用本地模型，识别文字先供用户校对，确认后才保存为简历原文。TXT、Markdown、PDF、DOCX 文件会在本机提取文字并保存原始文件。AI 改进流程会在用户明确勾选同意后，在本地把原始简历切分成片段并按 JD/改进重点检索，再将命中的片段、相关结构化个人资料和可选 JD 发送给 `.env` 配置的 DeepSeek；返回结果先作为草稿，展示检索片段、资料依据和待确认信息，用户审核后才保存为新版本。待审核草稿刷新后会恢复；模型调用失败也会保存任务状态和可读错误，方便排查后重试。填写 JD 时会生成对应简历草稿和打招呼语，并把 JD 快照保存在版本中。首版 RAG 使用本地关键词匹配与简历分块，不依赖向量检索；没有词面命中时会提供明确标注的少量备用片段供人工重点核对。

JD 分类与资料匹配使用可解释的关键词规则，是审核辅助而非自动判断求职者是否胜任；每项匹配都需要用户核对。简历分块与结构化个人资料检索结果会带来源编号保存在本次任务快照中，模型引用只接受本次实际提供的资料编号。LangGraph 目前负责简历改进垂直流程的状态编排，不拆分多个子 Agent。当前属于可解释的关键词式 RAG，不是向量或语义检索；后续只有在实际检索效果不足时再评估混合检索。岗位记录支持手动录入、粘贴 BOSS 岗位文字整理导入，以及用户主动同步专用 Chrome 中的收藏列表或收藏岗位详情页；同步结果先预览，再由用户逐条确认导入。岗位包含筛选、跟进状态、备注、下一步行动和原始链接。当前不会自动投递。

前端开发模式：

```powershell
cd frontend
npm install
npm run typecheck
npm run build
cd ..
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

`frontend/dist` 已加入 `.gitignore`，部署或本地运行前需要先执行一次 `npm run build`。如果没有构建目录，FastAPI 会回退到兼容的旧版 Jinja 页面。

Chrome 同步说明：点击岗位记录中的“启动并打开 BOSS”，在专用 Chrome 窗口里手动登录 BOSS、进入“职位收藏”，再点击“同步当前页面”。收藏列表只展示读取到完整 JD 的岗位；若列表未能读取完整详情，请在同一个专用 Chrome 中点开收藏的岗位，等待详情加载完成后，再回到应用点击“同步当前页面”。收藏列表和从收藏列表打开的岗位详情页均可同步，结果先预览，用户逐条确认后才写入岗位记录。也可继续手动粘贴岗位文字导入。应用不会读取或保存密码，也不会自动提交投递。
