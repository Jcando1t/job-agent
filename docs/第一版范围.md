# 求职 Agent 第一版范围

## 产品目标

帮助求职者根据自己设置的岗位方向主动发现职位，判断职位与个人经历的匹配情况，并持续跟进申请进度。第一版先供项目创建者本人使用；数据和功能按未来支持多个用户的方向设计。

## 已确定的使用方式

1. 用户可以新增、修改、暂停和删除多个求职方向，不把岗位名称写死在程序里。
2. 每个求职方向可配置岗位名称、搜索关键词和城市。初始城市为北京、天津，用户之后可以自行更改。
3. 用户可以逐步维护个人经历和技能，不要求先准备完整简历。
4. 第一版由用户手动发起 BOSS 直聘职位搜索。系统整理职位信息、识别重复职位，并按求职方向展示结果。
5. 系统将职位要求与用户提供的经历逐项对照，说明匹配依据、经历缺口和需要用户补充的信息。
6. 用户可以收藏职位并记录申请状态、面试进度和备注。
7. 用户确认后才能执行投递、联系招聘方等对外操作。第一版不做自动投递。
8. 后续再加入定时搜索和新职位提醒；这不属于第一版验收范围。

## 第一阶段：求职方向管理

先完成一个不依赖招聘平台的功能切片：用户能维护多个求职方向，设置岗位名称、关键词、城市和启用状态；数据保存在本地，重启应用后仍然存在。

### 验收标准

- 可以新增两个不同的求职方向，并分别设置关键词和城市。
- 可以查看、编辑、启用、暂停和删除某个方向。
- 北京和天津是初始可选城市，同时允许用户添加其他城市。
- 关闭并重新打开应用后，已保存的求职方向仍然存在。
- `.venv`、密钥和个人简历内容不会被提交到 Git。

## 后续阶段

1. 逐步建立个人经历档案。
2. 核实 BOSS 直聘可行的职位搜索接入方式，再实现手动触发搜索。
3. 加入职位去重、匹配分析和申请跟进。
4. 核心流程稳定后加入定时搜索和提醒。
5. 根据实际使用反馈扩展登录与多用户支持。

## 需要在实现时验证的事项

BOSS 直聘的搜索接入方式需要在动手接入前核实。职位数据应保留来源和原始链接；如果自动读取方式不稳定，则提供手动导入职位链接或描述的补充流程。
